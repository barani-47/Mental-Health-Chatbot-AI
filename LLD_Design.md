# Low-Level Design: Personalized Mental Health Support Chatbot

## 1. System Architecture
[cite_start]The system follows a modular architecture designed for scalability and maintainability[cite: 168]:

* **User Interface Layer**: Streamlit web interface for real-time interaction.
* **Preprocessing Engine**: Tokenization and vectorization using `text_vectorizer.pkl`.
* **Deep Learning Emotion Classifier**: MLP model (`mental_health_dl_model.pkl`) for emotion detection.
* **Agentic Orchestrator**: Logic layer combining user input with emotion context.
* **Generative AI Layer**: Gemini API for empathetic response generation.
* **Memory & Context Layer**: `st.session_state` management for conversational history.

## 2. Database Schema (Proposed for Production)
[cite_start]While currently using session-based memory, the production-ready schema for persistent storage is defined below[cite: 171]:

| Field Name | Data Type | Description |
| :--- | :--- | :--- |
| `session_id` | UUID | Unique identifier for the conversation session |
| `user_id` | String | Identifier for the specific user |
| `timestamp` | DateTime | When the message was sent |
| `user_input` | Text | Raw text provided by the user |
| `detected_emotion` | String | Emotion predicted by the DL model |
| `ai_response` | Text | Response generated by the GenAI Agent |

## 3. Design Considerations
* [cite_start]**Scalability**: Decoupling the AI inference from the UI allows for future horizontal scaling[cite: 168].
* [cite_start]**Security**: API keys are managed via secure secret vaults (`st.secrets`) to prevent data leaks[cite: 184].
* [cite_start]**Maintainability**: Modular component design ensures each part of the pipeline (ML, DL, GenAI) can be updated independently[cite: 168].
